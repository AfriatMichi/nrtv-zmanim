# שליפת זמני תפילות — בית כנסת נווה רחמים

שולף את זמני התפילות מ־<https://nrtv-production.up.railway.app/> **בדיוק כמו שגולש רואה אותם**:
דפדפן Chromium אמיתי טוען את האתר, מריץ את ה־React, וקוראים את מה שנצבע על המסך.
אין כאן שום שחזור של האלגוריתם שמחשב את הזמנים ואין ניחושים — רק קריאה של הדף.

רץ אוטומטית פעם ביום ב־GitHub Actions ושומר את התוצאה כ־JSON בתוך הריפו.

## למה דווקא ככה

האתר הוא SPA: התגובה הראשונה מהשרת היא `<div id="root">` ריק, וכל הטקסט נכתב ב־JavaScript.
בנוסף — **אין באתר אף `class` ואף `id`**, כל אלמנט הוא `<div>` חשוף. לכן:

* `curl` / `requests` לא יביאו כלום → צריך דפדפן אמיתי (Playwright).
* סלקטורים של CSS לא רלוונטיים → החילוץ מתבצע **לפי הכותרות בעברית**:
  מוצאים את `זמני תפילות` / `זמני היום` / `שיעורי תורה`, ומשם קוראים את שורות
  ה"תווית → ערך" שמתחתן. בדיוק כמו שאדם קורא את הדף בעיניים.

## מבנה

| קובץ | תפקיד |
| --- | --- |
| `extract.js` | פונקציית החילוץ שרצה **בתוך הדף**. כאן משנים אם מבנה האתר משתנה. |
| `scrape_zmanim.py` | מריץ את הדפדפן, לוחץ על הטאב `שבת`, מרכיב את ה־JSON. |
| `.github/workflows/zmanim.yml` | הרצה כל שעתיים + commit של התוצאה. |
| `data/zmanim.json` | הזמנים העדכניים — נדרס בכל ריצה. |

## שימוש ממערכות אחרות

הריפו ציבורי, אז ה־JSON נגיש ישירות בלי אימות:

```
https://raw.githubusercontent.com/AfriatMichi/nrtv-zmanim/main/data/zmanim.json
```

* מוגש עם `Access-Control-Allow-Origin: *` — אפשר `fetch()` ישירות מדפדפן.
* יש **cache של כ־5 דקות** ב־CDN של GitHub. אחרי עדכון ייתכן שתקבל עדיין את
  הגרסה הקודמת; להקפצה מיידית אפשר להוסיף פרמטר משתנה, למשל `?t=1724700000`.
* ללא הגבלת קצב משמעותית (בניגוד ל־API של GitHub שמוגבל ל־60 בקשות/שעה ללא טוקן).

## הרצה מקומית

```bash
pip install -r requirements.txt
playwright install chromium
python scrape_zmanim.py
```

## נקודות שכדאי לדעת

* **ההודעות הן קרוסלה.** בלוק `הודעות` מתחלף כל ~8 שניות, ו־React משאיר בכל
  רגע רק את השקופית הפעילה ב־DOM. לכן קריאה אחת תופסת הודעה אחת בלבד. הסקריפט
  צופה בקרוסלה סבב שלם, אוסף את כל השקופיות, ועוצר ברגע שהיא חוזרת להתחלה
  (בפועל ~20 שניות). השקופיות ממוינות כדי שהסדר יהיה יציב בין ריצות.
* **`selichot` נגזר מההודעות, לא מטבלת הזמנים.** מנייני הסליחות מתפרסמים
  כטקסט חופשי בקרוסלה ולא כשורות בלוח, אז יש להם פענוח נפרד. **זה עונתי** —
  מחוץ לאלול/תשרי השקופית פשוט לא קיימת והשדה יחזור `[]`. זה מצב תקין, לא תקלה.
* **רוחב החלון קובע!** האתר רספונסיבי ויש לו **שני מבנים שונים לגמרי**. הסקריפט
  מקבע `viewport` צר (430×1400) בכוונה — במבנה הצר מוצגות כל **10** שורות
  `זמני היום` (במבנה הרחב מוצגות 5 בלבד), והטאבים `חול`/`שבת` הם `<button>`
  אמיתיים. אל תשנה את הרוחב בלי לבדוק מה נשבר.
* **אזור זמן.** הדפדפן מורץ עם `timezone_id="Asia/Jerusalem"` ו־`locale="he-IL"`.
  בלי זה הראנר של GitHub (שרץ ב־UTC) עלול להציג יום אחר או "מניין הבא" שגוי.
* **תזמון.** ה־cron הוא `30 */2 * * *` ב־UTC — כל שעתיים, בשעות זוגיות ב־:30.
  בישראל זה נופל על 01:30, 03:30, 05:30 וכן הלאה, כך שתמיד יש ריצה אחרי חצות
  (התאריך העברי והזמנים מתעדכנים ליום החדש תוך שעתיים) וכמה ריצות לפני שחרית.
  אפשר גם להריץ ידנית דרך **Actions → Fetch zmanim → Run workflow**.
* **הטאב `שבת`.** נלחץ אוטומטית וגם הוא נשמר ל־JSON. אם הלחיצה נכשלת, הריצה
  ממשיכה ומדפיסה אזהרה — זמני החול עדיין נשמרים.
* **commit רק כשמשהו באמת השתנה.** `scraped_at` ו־`next_minyan.countdown` זזים
  בכל ריצה, אז אם רק הם השתנו ה־Action מדלג על ה־commit. זה לא משפיע על מה
  שה־URL מגיש — התוכן זהה ממילא. שים לב: המשמעות היא ש־`scraped_at` בקובץ
  יכול להיות מלפני כמה שעות גם כשהזמנים עדכניים לחלוטין.
* **הגנה מפני שינוי באתר.** אם לא נמצאו זמני חול בכלל, הסקריפט מחזיר קוד יציאה 1
  וה־Action נכשל — כדי שתדע שמשהו השתנה, במקום לשמור קובץ ריק בשקט.
* **`tzdata`.** נדרש כי ל־Windows אין מסד אזורי זמן של IANA. על ראנר Linux זה מיותר
  אבל לא מזיק — מופיע ב־`requirements.txt` כדי שהסקריפט ירוץ זהה בכל מקום.
* **הרשאות.** ה־workflow עושה `git push`. צריך ש־Settings → Actions → General →
  Workflow permissions יהיה **Read and write permissions**.
